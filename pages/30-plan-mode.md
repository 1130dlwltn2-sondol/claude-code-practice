# Part 3. 심화 기능

## 30. 계획 모드

계획 모드는 코드를 고치기 전에 계획을 먼저 세우는 방식입니다. 복잡한 작업일수록 먼저 계획을 보고 검토한 뒤 실행하는 것이 안전합니다. "이 기능을 이렇게 구현하려고 하는데, 계획을 세워줘"라고 하면 Claude Code가 단계별 계획을 제시합니다.

계획이 나오면 검토합니다. 빠진 단계는 없는지, 위험한 변경은 없는지 봅니다. "3단계에서 이 파일도 함께 고쳐야 해"처럼 피드백을 주면 계획이 수정됩니다. 계획이 마음에 들면 실행을 승인합니다. 그러면 계획대로 진행됩니다.

계획 모드가 특히 유용한 경우는 세 가지입니다. 첫째, 여러 파일을 건드리는 큰 변경입니다. 둘째, 되돌리기 어려운 변경입니다. 데이터베이스 마이그레이션 같은 것입니다. 셋째, 처음 보는 코드베이스입니다. 계획을 보면서 구조를 파악할 수 있습니다.

계획과 실행을 분리하는 습관은 협업에도 도움이 됩니다. 계획을 문서로 남기면 팀원이 검토할 수 있고, 나중에 왜 그렇게 했는지 추적됩니다. 큰 작업은 계획 모드가 기본값이라고 생각하세요.

실습: 계획 먼저 세우기
1. 복잡한 작업 하나를 정하기 (예: 새 API 엔드포인트 추가)
2. 계획 모드로 계획 수립 요청하기
3. 계획을 검토하고 피드백 주기

핵심 정리
- 복잡한 작업은 계획부터 세우고 검토한 뒤 실행한다.
- 계획에 피드백을 주면 수정되어 돌아온다.
- 되돌리기 어려운 변경일수록 계획 모드가 필수다.
